# Resident Greenfield window viewer (Desktop client)

The resident compositor contract in [ADR-0040](../decisions/0040-resident-greenfield-window-media.md) replaces browser ownership of Greenfield signaling. The Desktop client obtains a live `SurfaceAttachment.id` through `AttachSurface`, keeps that attachment while its Core native workload window exists, and uses `GreenfieldWindowService` for window facts, frames, input, and clipboard. Closing the WorkOS top-level window removes its Core anchor and detaches this viewer. Only the explicit Stop action stops the workload.

`NativeApp` remains the workload lifecycle host. For a Greenfield session it starts `GreenfieldWindowProjection`; for the existing Xvfb engine it keeps the WebRTC path. The projection consumes complete `WatchGreenfieldWindows` snapshots tied to the session and workload generation. Desktop projects each native top level and transient into a `native-window` entry in the existing WorkOS window manager. The Core window is a hidden lifecycle anchor while native top levels exist, so a second blank manager window is not displayed. Runtime window IDs and parent IDs remain local projection facts, never new Core desktop targets. A native title bar focus sends the sequenced focus event; a rejected focus is shown as an error.

Each native child subscribes to `WatchGreenfieldWindowFrames`. `GreenfieldFrameAssembler` checks the generation, window revision, frame sequence, tile bounds, PNG signature, and exact full-frame coverage. The canvas decodes every tile and draws a complete frame before reporting ready. A new subscription requires another full refresh; a gap, resize, or revision change cannot be filled with stale deltas. A 10-second first-frame timeout reports unavailable. Snapshot disconnects cover old pixels and disable input; definitive authorization denial removes projected windows. The client retains no media cursor across a new attachment.

Within the Core workload's one z-order slot, each native top level and its transients form a stacking family. Desktop raises the whole family when local focus raises any member, and always places descendants above their parent even if the reducer temporarily gives the parent a higher local z-index. Other WorkOS windows still follow Core z-order. Locally dragged or resized native-window bounds survive a complete Runtime window snapshot for the same window identity; the viewer requests a fresh native frame at the new content size.

`GreenfieldWindowInputClient` serializes one sequence across all native windows for this attachment. `NativeSessionLease` retains that client across responsive React body remounts of the same attachment, so a remount cannot reset the sequence. It sends the current control generation and retries an ambiguous response only with the same sequence. A rejected or unknown result disables subsequent input until a new viewer is attached. UI controls are disabled for observers, while Runtime remains the authorization boundary. Each visible native top-level window offers the observer a takeover action because the lifecycle host is minimized while top levels exist. A successful takeover updates the same attachment's control generation before enabling input; subsequent window snapshots preserve that state. Pointer coordinates account for CSS letterboxing. Physical keys use Chromium `code`; Mac editing shortcuts map to Linux Control. The hidden textarea commits IME text once. Browser clipboard reads and writes are initiated by a user action, bounded to 1 MiB, and surface permission or native selection failures. A paste acknowledgement means the command was accepted, not that the application consumed the text.

A projected child with a current `parent_window_id` has a separate title-bar Close path under [ADR-0041](../decisions/0041-native-transient-window-close.md). Desktop sends a sequenced `GreenfieldWindowClose` through the same controller input client and keeps the child visible until Runtime's complete snapshot removes its ID. Runtime checks that the window and its parent are still present under the current workload generation; the resident child resolves the exact current client/surface and asks only that top-level role to close. A controller or connection failure, or a child that stays visible after the request, produces an explicit error. A parentless top-level still closes the Core anchor and never sends a native close request.

The deterministic fixture and unit tests prove client projection, frame assembly, sequence handling, and UI states. They do not prove real Code pixels, two-device observation, native focus, standard Chromium IME, browser clipboard permissions against the live HTTPS Gateway, or input-to-visible latency. Those remain P0 integration acceptance cases with Runtime and Gateway. A physical second device is a separate unverified scenario, not a macOS-specific P0 gate.
