# Terminal browser clipboard (P0)

The Desktop Terminal window remains a client of the supervised Runtime PTY workload (ADR-0028). It does not create a second shell or a browser-local terminal. The existing `PtySessionService.WritePtySession` contract accepts at most 16 KiB of raw bytes per call and rejects NUL. No protocol or database change is required for text clipboard support.

`TerminalApp` handles copy and paste only from a browser user action. Ctrl+C with a selection inside the Terminal output, Cmd+C with a selection, and **Copy selection** write that selected text to the browser clipboard. Ctrl+C without a selection sends ETX (`0x03`) to the PTY. Ctrl+V, Cmd+V and **Paste** read the browser text clipboard; a native paste event on the focused Terminal output uses its `text/plain` payload. Clipboard API absence or denial, empty/NUL/oversize text, and unconfirmed PTY writes produce visible status text. The copy/paste budget is 256 KiB of UTF-8 text, not the old 256-character input limit.

One clipboard gesture reserves its position in the Terminal's ordered input queue before the asynchronous browser clipboard read finishes. Text is encoded once, split at UTF-8 code point boundaries into writes of at most 16 KiB, and sent sequentially to the same session and control generation. If a chunk fails, later chunks and input already queued under that generation are cancelled. Because `WritePtySession` has no operation id or replay-safe acknowledgement, the UI reports an unconfirmed paste and asks the user to inspect shell output before retrying. It never labels an uncertain partial write successful.

Only the current controller can write. The browser checks local control and expiry before enqueue and before each chunk; Runtime checks device plus generation on every RPC. The Terminal renews only its existing attachment with `RenewSurfaceControl`; a denied, expired or superseded lease becomes observer. Only the visible **Take control** action calls `RequestSurfaceControl`. Observers can copy output but cannot paste or type. A closed Terminal window detaches and leaves its supervised workload running under its lifecycle policy.

`terminalClipboard.test.ts` covers UTF-8 chunk integrity and bounds. `TerminalApp.test.tsx` covers copy versus ETX, queue reservation, failure, and control loss. `terminal-clipboard.spec.ts` exercises the actual Chromium clipboard API and keyboard shortcuts against a deterministic Connect fixture. The separate real PTY and owner-authenticated LAN browser gates remain the evidence for whole-system operation.
