## 1. 唯一任务与交付产品

**本次只做 V3 P0：交付接入现有 WorkOS 浏览器桌面的原生体验验证版本。**

Linux 服务端运行官方桌面版 VS Code；浏览器通过 Greenfield 合成路线显示并操作真实应用
窗口。用户在 WorkOS 中编辑文件、输入中文、复制粘贴、调整窗口；关闭所有浏览器后，
原应用仍在服务端运行，重新进入或换设备可以附着同一实例。

这是一份“大类任务”。下文 W01–W07 是它内部的串行工作包，依次完成可推进的部分，
不要要求用户逐包派活，也不要同时启动多个写入智能体。

### 1.1 用户应该得到什么

1. 按文档启用 P0 后，从现有 WorkOS 桌面启动真实桌面版 VS Code，打开确定性测试项目。
2. Code 与辅助原生应用属于同一个 WorkOS 桌面，菜单、弹窗、焦点与窗口操作正常。
3. 使用键盘、鼠标和输入法直接操作应用，双向复制多行文本；不依赖“填表后发送文字”。

5. 关闭窗口、刷新、断网和关闭全部浏览器后，仍能连接原 Workload／generation；
   显式 Stop、应用内退出和 Restart 有准确且不同的结果。

P0 可以使用专用 fixture、固定镜像和显式启用的实验入口。它尚不是 P1 的完整日常开发电脑。

## 4. 必须保持的行为

- **同实例**：恢复同时核对 Workload ID、generation、Runtime 进程／容器身份与活状态。
  不能只看 UUID、截图、同名窗口或重新打开的文件。进程退出后显示真实终态。
- **无浏览器保活**：所有交互客户端断开后，服务端显示会话和应用继续运行；保活不依赖
  用户留下某个标签页。确需常驻辅助组件时由 Runtime 管理，记录成本与故障语义。
- **关闭语义**：WorkOS 窗口关闭是 detach；应用内退出是真实退出；Stop 结束受监督程序；
  Restart 按既有规则产生新 generation。关闭一个应用不应误停同显示环境的其他应用。
- **控制代次**：多设备观察与单控制端分开；观察不抢占控制，显式接管后旧连接、排队输入、
  resize 和迟到续约失效。P0 不新增 AI GUI 自动化，但不得绕过现有代次校验。
- **本地响应**：拖动、光标由浏览器及时响应；应用按实际窗口尺寸／DPR 重绘。
  静态文字必须有无损刷新路径，不能只提高低码率视频的分辨率或长期拉伸旧帧。
- **文本完整**：剪贴板有独立的有界传输和结果，不把长文本塞进旧 256 字符输入事件后截断。
  不裁剪空白或重复提交 composition；失败、过期、拒绝访问不能用缓存旧值冒充成功。
- **保护持续有效**：长期运行不等于永久授权。连接、媒体和输入仍需有效权限；失去权限
  关闭访问，控制和运行策略继续按已接受 ADR 执行。

   有测试。首版不增加图片、富文本或文件拖放。

## 7. 检查命令与工具链

具体功能测试由 W06 创建和验证；不要只把不存在的命令写进结果表。
仓库已有门禁默认从根目录运行：

```sh
make generate
make check
git diff --check
```

`make generate` 后，确认生成文件与当前 Proto／Schema／查询匹配；提交前再生成不产生
额外内容变化。若本轮确实改了契约，生成代码相对旧 HEAD 有差异是正常的，不能因此删除它。

宿主没有 make/Go/Node 时，复用仓库固定工具链。以下是运行 `make check` 的已有方式；
运行 generate 或其他 make target 时只替换最后的 target，记录你真正执行的命令：

```sh
docker run --rm --user "$(id -u):$(id -g)" \
  --group-add "$(stat -c %g /var/run/docker.sock)" \
  -v /usr/bin/docker:/usr/bin/docker:ro \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v "$PWD:$PWD" -w "$PWD" \
  golang:1.26.7-bookworm make check
```

这是检查工具容器的 Docker 访问方式，不是允许把 socket 挂给 VS Code、应用或 Harness。
新的 P0 门禁需要什么图形依赖、端口和镜像，在 W02/W06 核对后写入运行说明；不猜安装命令。
