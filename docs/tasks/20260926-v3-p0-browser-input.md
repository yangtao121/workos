# V3 P0 browser input and clipboard

- Status: in_progress.
- Owner: Desktop Web, branch `feat/v3-p0-browser-input`.
- Scope: adapt Greenfield canvas to standard Chromium input, composition, focus, clipboard gestures, clear success/failure, and controller gating. Preserve Xvfb Native path.
- Dependencies: Greenfield runtime attach and real selection support in `20260924-v3-p0-native-experience`; secure LAN HTTPS for Clipboard API.
- Acceptance: Mac Chrome/Edge users can type Chinese text and use common editing shortcuts in real Code; text clipboard works both directions with explicit user gestures, including emoji, tabs and multiple lines; observer cannot send input; focus loss releases keys; tests and visual records support the behavior.
- Visual evidence: [`before/`](../ui/desktop-web/changes/20260926-v3-p0-browser-input/before/), [`after/`](../ui/desktop-web/changes/20260926-v3-p0-browser-input/after/), [notes](../ui/desktop-web/changes/20260926-v3-p0-browser-input/notes.md), and [current unavailable state](../ui/desktop-web/current/greenfield-window--unavailable--1440x900.png). These show the unavailable fixture only; they are not a real Code screenshot.
- Implementation: direct canvas pointer, wheel, and keyboard binding for pinned Greenfield; hidden textarea forwards committed Chromium IME text through Wayland selection; Mac Meta editing shortcuts map to Linux Control, while physical Ctrl+C remains with the app. User-gesture copy reads a fresh app text selection and writes the browser clipboard. Paste reads the browser clipboard and sends a Wayland text offer plus Control+V. Both paths enforce a 1 MiB UTF-8 limit and report errors. NativeApp now passes the controller epoch from the surface lease, not the workload generation.
- Module documentation: [Greenfield browser input adapter](../architecture/greenfield-browser-input.md).
- Verification: `corepack pnpm --filter @workos/desktop-web check` (229 tests at that run), `corepack pnpm --filter @workos/desktop-web build`, final focused Vitest run (23 tests), typecheck, targeted ESLint, and `git diff --check` passed. Playwright Chromium browser fixture verified Clipboard API user gesture and composition event; deterministic Chromium visual capture passed at 1440×900 for before/after.
- Outstanding acceptance: A04 Mac Chrome/Edge Chinese composition and shortcut behavior, A05 real Code/terminal/graphical application clipboard round trips, and observer/server-side input gating need physical or live Wayland evidence. The Chromium fixture dispatches composition events but does not drive a physical OS input method or a real Code process. Upstream pinned proxy currently does not replay the window graph to a new browser and permits only one signaling connection; browser input gating cannot replace a server-side controller gate. No real clipboard or IME proof has been recorded, so this task remains in_progress.
