- Scope: observe the exact application process launched inside each resident child. An app's own Exit must retire its current workload generation as stopped; an unexpected child or application failure must retire it as failed. Reads and Home must report the durable terminal state, and Restart must create a new generation and child identity without reviving the old process.

No owner password enters repository tests or evidence.
- Initial finding: the bridge monitors proxy/Chromium only. Code can exit while the proxy stays alive, leaving a false `running` workload. Runtime currently maps every `display.Exited()` to `failed`, and native project discovery selects only queued/running rows, hiding terminal Restart.

## Implementation

- The pinned compositor rc1 patch now forwards proxy `APP_TERMINATED` exit code or signal to the resident browser callback. The bridge emits an exact-generation terminal window snapshot with no windows: exit code 0 is STOPPED; nonzero exit or signal is FAILED. A separate `/proc/<pid>/stat` starttime monitor treats vanished, zombie, or reused PIDs without a terminal signal as failure after a short signaling grace. Empty windows alone never imply application exit.
- A clean application Exit now returns child exit code 0. The Runtime Docker supervisor lets an already accepted terminal snapshot determine the state and gives an absent child without a snapshot two seconds to deliver its final IPC record. Runtime reconciles STOPPED to durable Native `closed` (Surface `stopped`); failures remain `failed`. Project discovery reconciles active rows immediately, includes every active row and up to 16 recent terminal Native rows, and leaves old generations unavailable for input.
- Home labels the combined list “App sessions,” shows stopped/failed Native rows with Open disabled and Restart enabled. `tools/lan/test-code-p0.sh` can write an owner-only results pointer only after its baseline gate passes. The independent `tools/lan/test-code-a08.sh` reads that pointer **after** auxiliary app isolation, verifies the original Code child identity survived, runs CA-trusted Chromium File→Exit and Restart, kills only the newly recorded exact child, then verifies failed and a fresh Restart identity. It leaves the last Code child running for the later A07 gate.
- Module behavior is documented in [Runtime lifecycle](../architecture/runtime-lifecycle.md) and [Greenfield window viewer](../architecture/greenfield-window-viewer.md). Proto was unchanged: `GreenfieldWindowSnapshot.state` already contains STOPPED and FAILED.
