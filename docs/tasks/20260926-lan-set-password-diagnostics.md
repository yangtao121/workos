## Diagnosis and verification

- The exact error string is produced only by Gateway `verdict()` for `domain.ErrInvalidRequest`; `PasswordService.SetPassword` can produce that verdict only when the submitted username fails its 1–80 rune, no-control-character grammar or the password fails its 12–1024 valid UTF-8 byte grammar. The old CLI checked only that the two password entries matched, so it sent malformed input and displayed a field-neutral server error. The sanitized server response intentionally does not identify which field failed; because the owner's input was neither logged nor inspected, the exact rejected field in the historical attempt cannot be recovered. The code change makes a retry identify the category before RPC without displaying its contents.
- Gateway application and CLI now call the same Gateway-domain validators. The CLI reads username one byte at a time from the terminal, preventing a buffered username reader from consuming bytes for the subsequent `term.ReadPassword` prompt. It rejects invalid username or password before contacting the private admin socket, reports the applicable constraint without echoing values, and clears the temporary password byte slices after use.
- `start.sh set-password` now validates the Gateway-only Compose file and a live private admin Unix socket before starting the interactive CLI. It does not run `cert.sh`, rebuild containers, or mutate a leaf certificate. A missing admin socket gives an actionable error before the password prompt.
- Verified `go test ./cmd/workosctl ./internal/gateway/auth/... -count=1` in `golang:1.26.7-bookworm`; all packages passed. The domain test covers valid boundary sizes and invalid UTF-8/control/length cases without printing candidate values. The CLI test confirms the username reader leaves the next prompt's bytes unread. `sh -n tools/lan/start.sh tools/lan/test-set-password.sh`, `sh tools/lan/test-set-password.sh`, and `sh tools/lan/test.sh` passed. The shell test uses a fake Docker command to verify admin preflight/order, lack of TLS material issuance, and no CLI prompt path when the socket is absent; it never handles a real password.
- A live owner password was not set or read by this task. The owner can retry only after the updated Gateway image is built and running; the LAN integration owner will record successful login and browser evidence separately.
